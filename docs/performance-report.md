# 电脑端性能报告

用来回答两个问题：**卡的时候是谁在占用电脑**，以及**计时器自己有没有问题**。入口在 **设置 → 性能**。

监测默认关闭，自己点了才开始；数据只写在本机的 debug 目录，不会上传，也不录制游戏画面。

## 怎么用

1. 打开 **设置 → 性能**，点 **开始监测**。主浮窗的“设置”按钮会变成“设置 · 监测中”。
2. 正常玩。出现卡顿时点 **标记卡顿**（报告会在曲线上标出那一刻，并自动抓一段 CPU 采样）。
3. 点 **停止并生成报告**，弹窗里可以直接打开文件夹。把 `performance-report.zip` 发给开发者。

关闭设置窗口不会停止监测。直接退出程序也会先把报告写好。如果程序被强制关闭或崩溃，下次打开后点 **生成上次记录的报告** 即可（损坏的最后一行会被跳过）。

单次最长记录 6 小时。建议至少包含一两分钟的正常阶段和卡顿阶段。

## 标签页上能看到什么

- **四个数字**：整机 CPU、计时器 CPU、整机内存、整机 GPU。
- **一句话判断**：计时器内存、模拟器的 CPU/内存、本秒最慢的一轮识别；整机很忙而计时器占得很少时会直接说明。
- **谁在占用资源**：全系统占用最高的程序（同名进程合并），模拟器会标出来。
- **开发者明细**（默认收起）：硬件、识别链路各阶段耗时、全部指标、没测到的数据及原因。

## 报告里有什么

解压 ZIP，打开 `report.html`（不需要联网）：

- **结论**：几句话说明这次记录里发现了什么，例如“整机 CPU 长时间偏高（平均 92%），其中计时器占 3%；占用最高的是 MuMuVMMHeadless.exe（平均 70%），瓶颈不在计时器”。
- **关键数字**：时长，整机 / 计时器 / 模拟器的 CPU、内存、GPU，单轮识别最长耗时，卡顿标记、慢帧、采集错误次数。
- **谁在占用资源**：整段记录里各程序的平均和峰值 CPU、内存、GPU、显存。
- **手动卡顿标记**：每次标记的钟表时间和记录内时间。
- **时间曲线**：横轴是时分秒，鼠标移上去能看到对应的钟表时间；红色竖线是卡顿标记。
- 折叠区：全部指标、计时器进程明细、没测到的数据及原因、附件列表。

其他文件：

| 文件 | 内容 |
|---|---|
| `report.md` | 文字版摘要，可直接贴到聊天里 |
| `summary.json` | 全部统计 |
| `samples.csv` / `samples.jsonl` | 每秒原始数据 |
| `metadata.json` / `status.json` | 电脑、构建信息、记录状态与错误原文 |
| `config.json` | 记录时的完整设置 |
| `heap-*.pprof` / `goroutines-*.txt` / `cpu-*.pprof` | 开发者调试数据（可在开始前取消勾选） |

开发者查看 CPU 热点：

```sh
go tool pprof -top cpu-mark-1.pprof
go tool pprof -base heap-start.pprof heap-end.pprof
```

## 读数说明

- **CPU 百分比按全部逻辑核归一**，和任务管理器“进程”页一致：100% 表示所有核心满载。
- **“—” 表示没测到，不是 0。** 进程的 CPU 占用需要连续两次采样；GPU 占用率需要预热一秒。
- **GPU 是最忙引擎的占用**，不把 3D、视频解码等不同引擎相加。没有 GPU 上下文的进程按 0 计。
- **模拟器按进程名识别**（MuMu、雷电、BlueStacks、夜神、逍遥、腾讯手游助手）。其他程序同样会出现在进程榜里，只是不带“模拟器”标记。
- **进程榜每秒只记录占用最高的若干进程**；平均 CPU 按整段记录计算，没上榜的时刻按 0 计。
- **每秒内最慢的一轮**：每个采样窗口保留截图、识别、整轮循环的最大值，采集失败和超时也计入耗时，所以一次几百毫秒的卡顿不会被平均掉。
- **内存增长趋势**只对内存、句柄、线程这类指标计算，并且需要至少 5 分钟的记录；它是线索，不是泄漏结论。
- 计时器内存合计可能重复计算共享页。

## 限制

- GPU 数据来自 Windows 的 GPU 性能计数器，需要 Windows 10 1709 以上和 WDDM 2.x 驱动；驱动响应慢时 GPU 数据会标为“已 N 秒未更新”，不影响 CPU 和内存的记录。
- 监测本身有少量开销（每秒一次系统进程枚举和计数器读取）；采样自身耗时记在 `collector_ms`。
- 历史记录保存在 debug 目录的 `performance/perf-时间-标识/` 下，不会自动删除。
- Linux 上只用于开发自测，没有 GPU 数据。

## 验证入口

```sh
# 记录器、采集器、报告
go test -race ./internal/diagnostics
# 设置页前端与生命周期
go test -race -tags ci ./internal/ui -run Performance
# 在本机实采并保留一份可打开的报告
NARUTO_PERFORMANCE_SMOKE_DIR=/path/to/out \
  go test ./internal/diagnostics -run '^TestPerformanceLiveExport$' -count=1 -v
# 渲染“性能”标签页截图
NARUTO_PERFORMANCE_UI_SMOKE_DIR=/path/to/out \
  go test -tags ci ./internal/ui -run TestPerformanceVisualSmoke -count=1
```

Windows 专属的采集代码（全系统进程枚举、GPU 计数器）只能在 Windows 上实际运行：发布流程会在 Windows 上跑 `go test -race ./internal/diagnostics`。
