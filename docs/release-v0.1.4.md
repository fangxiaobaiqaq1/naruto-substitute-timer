# v0.1.4

修复训练营待机扫光经过豆条时，可用豆数频繁跳为问号的问题。十尾带土的紫豆中心会被扫光照成白色；神农的金豆扫光则会使邻近间隔同样变亮。现在用当前帧的彩色豆体、连续内侧像素及两侧/下方分隔确认这些高光，不缓存旧豆数，不放宽无帧或遮挡的事件判定。

未选边时的替身次数由「左0 / 右0」改为「左0次 / 右0次」，与底部豆数区分。保留 v0.1.3 内置 OCR、完整资料库、对局录制与真实绘制阶段诊断。

验证：

- 修复前连续20秒、900帧中有183帧右侧豆数未知，场景及采集均正常。
- 修复后十尾带土训练营待机连续30秒、1399帧均为左4/右4，没有未知豆数；没有采集错误。
- 23张本机待机原帧回归通过；空紫豆加白光、白色/紫色大片遮挡、空心边框等反例不能变成亮豆。RGB、界面、场景连续性、采集和诊断相关测试通过。
- 用户提供的斑原生截图可读出左4/右6。本次没有斑连续扫光录像，不能将带土的连续测试结论扩展到所有六槽场景。

以上是待机画面稳定性验证，不是完整对局准确率，也不是端到端延迟测试。用户原帧及账号资料不随包发布。

先退出旧程序，再运行新版 `timer-app.exe`，诊断应显示 **v0.1.4**。Windows x64 仍需 Microsoft Visual C++ v14 x64 运行库，第三方许可见 `THIRD_PARTY_NOTICES.md`。
