# v0.1.5

修复本地 OCR 启动失败与神驹佑祥斑六槽豆条的白色扫光闪跳。

- Windows 10/11 x64 版将 OCR 模型、ONNX Runtime 与所需四个 Visual C++ 运行库 DLL 一起编译进 EXE。首次运行按整套文件哈希释放和校验，损坏缓存会重建。通过隔离工作进程、限定目录预加载及实际模块路径核对，避免继承的旧 DLL 搜索目录覆盖内置依赖。
- 「诊断 → 打开 OCR 启动日志」可直接打开日志。Windows 错误 1114、126、193、5 分别显示初始化、依赖、格式、权限问题；完整原因、程序版本/路径、错误码和已加载模块路径保留在用户缓存目录的日志中。只保留最后一次失败和最新成功状态两个小型 JSON，不保存截图；成功重试不会清掉失败证据。
- 神驹斑已确认的六槽红橙豆使用当前帧上下豆体和槽间分隔验证白色扫光。遮挡和空槽仍保持未知，不用上次豆数掩盖画面变化。保留完整忍者资料库、OCR、对局录制与分阶段延迟诊断。

验证范围：

- 旧版在父进程继承 Java 的旧 VC DLL 搜索目录时稳定复现同一「DLL initialization routine failed」错误；新版同环境成功启动并核对五个模块均来自内置缓存。此测试证明冲突机制，不假定用户现场一定来自 Java。
- 在全新缓存、无外部模型目录、系统 PATH 下启动实际 GUI EXE，验证本地 OCR 姓名识别、内置运行库路径与损坏缓存修复。
- 六槽扫光合成序列及真实斑截图像素回归通过：连续扫光/遮挡不产生替身事件，真实 6→5→5 只确认一次，事件时间取首次掉豆帧。尚无修复后神驹斑整场连续录像，不能据此承诺所有特效或整场准确率。

退出旧程序后运行本包 `timer-app.exe`，诊断页应显示 **v0.1.5**。完整名字资料、模型和运行依赖已内置，不需要 Python、外部名字图片库或自行安装 VC 运行库。原创代码为 MIT；微软运行库和其他第三方组件保留各自许可，详见 `THIRD_PARTY_NOTICES.md` 和 `licenses/`。
