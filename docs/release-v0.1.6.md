# v0.1.6

修复新版训练场出现「画面未识别 / 待识别 / 豆左?/右?」，即使豆条和神驹斑名称本身已能识别的问题。

训练场增加「复位、音乐」按钮后，「键位」文字右移且变大，旧场景入口无法匹配，程序因缺少有效场景证据而暂停显示豆数。现在复用原有文字模板，增加限定位置、1.125 倍尺寸的入口，阈值仍为 0.87；旧布局入口和未知画面保护继续保留。

默认场景清单及其图片、掩码随 EXE 内置更新。旧 ZIP 遗留的 assets/templates 文件不会盖住新版内置修复。需要自定义模板时，请复制清单为独立文件并设置 scene.manifest 为该自定义路径；显式自定义路径的外置读取行为不变。

验证：

- 用户原图修复前 Fighting=false、场景最高匹配分 0.2538；修复后识别为训练场，匹配分 0.9554，左4/右6且确认神驹斑。
- 原图及950、960、1280、1600、1920、2560宽度共七种尺寸均通过完整场景、名称及采豆链路；640–2560的场景测试也通过。
- 大厅、选人、搜索、VS、结果及禁用页面负样本保持拒绝。场景、引擎、RGB、UI和诊断回归通过。
- 当前模拟器连续12秒409帧均识别为训练场、无采集错误；该段画面为左4/右2，不将其当作原图右6豆或整场准确率验证。这里只是采集/判定检查，不是端到端延迟报告。
- 新 EXE 在无外部资源目录及残留旧默认清单的目录中，都使用完整内置场景库；显式自定义清单继续正常加载。

本版保留 v0.1.5 的完整 OCR、忍者资料库、ONNX/VC依赖、完整启动日志及六槽扫光修复。退出旧程序后运行 timer-app.exe，诊断中版本应为 **v0.1.6**。
