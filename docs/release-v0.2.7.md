# v0.2.7 · 神驹斑识别、采集选择与启动保护

## 修复内容

- `宇智波斑[神驹佑将]` 的规范布局改为 4 颗替身豆；暖色当前帧的扫光/白色高光判定仅在该已确认标题和有界豆体证据下启用，避免由旧身份或拓扑提示推断豆数。
- 「采集设置」直接提供自动（按回退顺序）、MuMu SDK、雷电 ADB、窗口截图（PrintWindow）四个后端。切换只修改待保存草稿，保留 `Provider` 和 `PreferredMethods`；选择雷电后会立即开始发现实例，无需先进入高级设置保存。发现结果会拒绝过期窗口、代次或后端的回调；界面统一使用「保存并应用」。
- `启动计时器.bat` 启动前探测 `bin\timer-app.exe --version`；缺失、版本不是 `v0.2.7`、探测失败或构建失败时不会启动旧二进制。重建使用 `TIMER_VERSION=v0.2.7` 与 `CGO_ENABLED=1`，并在启动前再次核验版本，同时保留工作目录和传入参数。

## 下载与更新

- 程序内更新默认读取 Gitee；可在「关于与更新」中选择 GitHub。
- 本次仅发布在线更新所需附件：`timer-app.exe` 和 `SHA256SUMS.txt`。下载后请用校验文件确认 SHA-256。
- 现有 `v0.2.6` 保留为回退版本。

## 验证与已知限制

- Linux 交叉构建只证明可生成 x64 PE，不构成 Windows、Fyne、MuMu、雷电或实机识别验收。
- Windows/MuMu 手工验收仍待完成；按 [`docs/windows-mumu-acceptance.md`](windows-mumu-acceptance.md) 执行 `timer-app.exe --version`、启动、各采集后端和替身识别检查。
- 未实现「带土误报修复」的声明；当前帧证据不足时仍保守显示未知，不根据旧豆数或身份猜测结果。
