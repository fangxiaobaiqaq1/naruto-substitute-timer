# v0.2.9 · Android 原生端、悬浮计时与采集性能

## 新增功能

- 新增 Android 原生计时器：在 Android 12（API 31）及以上通过 MediaProjection 或无障碍截图采集画面，复用 C++ 识别核心，并提供原生悬浮计时条、权限引导和设置页。
- Android APK 提供 `x86_64` 与 `arm64-v8a` ABI，包名为 `com.narutotimer`，版本号为 `0.2.9`（`versionCode 29`）。
- Windows 端新增独立迷你悬浮窗；支持无边框、透明度和字号调整，悬停后可打开设置、切换我方阵营、同时显示双方计时或退出。
- 双侧计时在阵营尚未确认时也可启动；自动认边、手动换边和迷你模式保持一致。
- 诊断工具新增采集与识别基准，可统计各采集后端的延迟、重复帧、有效 FPS、识别/OCR 分位数并导出 JSON。

## 性能与修复

- 雷电采集增加复用连接、原始 ADB 截图和窗口截图路径，按启动与逐帧阶段分别设置超时，并保留 PNG 路径作为回退。
- 头像、标题、场景和 RGB 识别采用有界并行；限制工作线程数量，避免占满模拟器资源；等价性测试确认分数和识别结果保持一致。
- 头像匹配缓存按像素内容复用，减少重复灰度转换和模板解码；界面状态未变化时跳过无效刷新。
- 修复神驹斑、夏隐红豆等特殊模板的识别边界和计时管线，避免旧身份、重复帧或 UI 刷新造成误判和漏报。
- Android 迷你悬浮窗自适应尺寸并立即应用无边框样式；修正悬浮窗阵营文案和场景标签。

## 下载与更新

- Windows 发布附件应至少包含 `timer-app.exe` 与 `SHA256SUMS.txt`，并使用 `v0.2.9` 标签；程序内可在 Gitee 与 GitHub 更新源之间切换。
- Android 发布 `naruto-timer-universal.apk`（`x86_64`/`arm64-v8a`）及对应 SHA-256 校验文件；安装前请确认包名、版本号和 ABI。
- 自动更新仍只在用户确认后下载和重启；下载完成后校验版本、大小和 SHA-256，失败时保留当前安装。

## 验证与限制

- 已覆盖 Go 端识别、采集、配置、更新和 UI 回归测试；Android 端构建需要 JDK 17、Android SDK 35、NDK 27.2.12479018、CMake 3.22.1 和 Gradle 8.11.1。
- Linux 交叉构建只证明 Windows PE 可生成，不替代 Windows/Fyne、模拟器连接和实机识别验收。
- Android 发布 workflow 要求稳定的正式签名 secrets；本地未配置密钥时只使用 debug fallback，不能把该产物用于后续在线更新。
