# 使用说明

## 首次使用

先运行 MuMu 或雷电和火影忍者，再打开计时器。Setup 为当前用户安装；便携 EXE 放在可写目录。

浮窗显示对面的冷却。首次在「设置 → 常规」选择我方左右位置；训练场没有账号认边证据时，手动选择即可。填写自己的游戏账号名可使用自动认边，不要填写忍者名代替账号。自动认边优先确认我方名字；若我方名字被特效遮住、但另一侧精确识别为**未填写的账号**，则将那一侧视为对面、我方取另一侧。两侧名字都不可靠时保持“待认边”，不会猜测。手机端是同一规则；「我的名字」填错时可能认错边。

## 模拟器与多开

当前支持两种采集 provider：MuMu 原生截图 SDK，以及雷电（LDPlayer）ADB 截图。雷电不需要额外 DLL；程序从你选择的安装目录寻找 `ldconsole.exe`、`adb.exe`，实例编号来自 `ldconsole list2`，默认实例 0 的 ADB serial 为 `127.0.0.1:5555`，实例 1 依次为 `127.0.0.1:5556`。如果端口被修改，请在高级设置中填写实际 serial。完整的云端 worker/RPC 接入协议见 [雷电适配与云端 Agent 方案](leidian-adapter.md)。

「设置 → 模拟器」默认自动检测：仅有一个实例运行游戏时连接它；多个实例同时运行游戏时提示选择，避免任意猜测。

打开模拟器选项卡会自动刷新窗口/进程列表，显示窗口名、PID和多开实例编号；点击一行即可切换。列表第一项为自动检测。一般不需要选择目录；未发现窗口时再展开高级设置指定目录和编号。保存的是稳定的多开编号，重启模拟器后PID变化也不影响选择。切换实例会清除计时并重新建立观测基线。

旧配置中非零实例编号仍按手动选择兼容。特殊旧版 MuMu 若没有实例枚举接口，可手工填写安装目录及编号；无法支持的截图接口会在诊断中说明。

## 常规设置

- 我方位置：左边、右边或自动。手动选择立即生效。
- 我的名字：用于自动认边，支持逗号分隔多个账号名。
- 指定对面忍者：留空自动；只有明确选择的完整版本会启用其特殊显示。
- 默认替身冷却为15秒；照美冥[五代目水影]和半藏[秽土转生]同时显示15秒/10秒候选，不重复增加次数。
- 内置 OCR 在后台识别，不向网络上传截图。

未知、遮挡、重复或乱序帧不参与新事件确认；已确认的倒计时继续按真实时间运行。


## 仅计时器（迷你悬浮窗）

- 「设置 → 常规」的浮窗显示选「仅计时器」，或按 `Ctrl+M` 切换。
- 窗口就是计时底板：按住拖动移动；拖右边缘调长度、拖下边缘调高度（数字随高度缩放），大小和位置都会记住。勾选「仅计时器贴合文字」恢复自动大小。
- 点一下底板展开：设置、换边、两边计时、退出迷你（回到完整浮窗）。

## 区域校准（特殊分辨率）

平板、带鱼屏或模拟器窗口比例特殊时，自动布局可能找不准豆和头像，可以自己框。

- 打开：「设置 → 常规 → 区域校准（豆/头像）」；手机：点计时卡片 → 设置 → 位置 →「区域校准」。
- 在对局或训练场画面上校准。白色虚线是这一帧自动识别实际用的区域（十字是豆心，另有「名字」「头像窗口」），对得上就不用改。
- 选左侧豆 / 右侧豆 / 左侧头像 / 右侧头像后拖出方框：豆框紧贴 4 颗豆，小点应落在每颗豆中间；头像框只框头像。只保存改过的框，没改的保持自动。
- 豆框按普通忍者的豆行保存；九喇嘛水门、侠隐佐助、百战鼬的豆行偏低，认出它们时会自动换算。
- 「导出方案」「导入方案」可在电脑和手机之间互传；「全部恢复自动」清除校准。

## 手机版（Android）

- 需要 Android 12 及以上。打开 App 按「开始使用」三步：开启无障碍服务 → 启动悬浮计时 → 授权录屏识别（推荐；不授权时用无障碍截屏，较慢）。
- 在「对局设置」填写「我的名字」（游戏账号名，与游戏里完全一致）即可自动认边，规则与电脑版相同；也可以手动选左边 / 右边。
- 悬浮卡片可直接按住拖动；轻点打开操作（设置、换边、两边、迷你 / 完整、退出）。大小、宽度、高度和不透明度在卡片设置的「外观」里调。
- 卡片尽量不要放在屏幕正上方：那里是决斗场判断对局开始的回合标志。

## MuMu 多开、SDK 自检与反馈

在「设置 → 模拟器」点击“扫描 MuMu 安装与实例”。列表按 **安装目录 + 实例编号** 显示，实例 `0`、`1`、`2` 是 MuMu 多开器编号，不是 Windows PID；不同安装目录都可能各自有实例 `0`。列表会尽量显示关联的 PID，无法从进程启动参数可靠确认编号时不会擅自当作实例 `0`。

“浏览安装目录”只更新待保存草稿。选择实例后点击“使用选中的进程”，或手动填写目录/编号后点击“保存并应用手动实例”，才会写入 `config.json` 并请求采集器切换。页面同时显示已保存配置、已请求应用配置、采集器已应用配置与最近连接错误。

“测试当前选择（不保存）”会在独立进程中执行 MuMu SDK 连接和一帧截图，不会修改配置。遇到问题可在「诊断」中点击“导出支持诊断包（ZIP）”；该包默认不含原帧 PNG，包含配置、MuMu 安装/实例/PID、SDK DLL、分阶段自检和现有日志。请将 ZIP 发到 BUG 反馈 QQ 群：**1109044204**。

## 关于与更新

浮窗「关于」进入版本页面。检查更新默认从 Gitee（国内）获取最新正式版，也可切换到 GitHub；下拉版本列表可查看日志和发布日期。网络失败时保留已缓存的历史记录，不冒充刚检查成功。

点击下载后可查看进度或取消。校验通过后点击「重启并更新」；建议离开对局后操作。升级仅替换 EXE，保留配置和日志；旁边的 `.previous` 是上一个可恢复版本。新安装器覆盖安装同样保留用户数据。

安装版设置位于 `%APPDATA%\NarutoTimer`；便携版位于程序目录。不要将便携 EXE 放入系统只读目录。卸载后如需删除个人数据，请自行确认该用户目录中的内容。


## 外观与自动更新

在「设置 → 常规 → 外观与更新」中可以调整计时浮窗：

- **窗口不透明度**：40%–100%，只影响计时浮窗，鼠标点击与置顶行为保持不变。
- **计时浮窗字号**：25%–300%，主读秒、双读秒、次数和状态文字一并缩放；窗口会自动留出所需空间。
- 两项均在拖动时立即预览，松开滑块后写入 `config.json`；「恢复默认外观」恢复到 100% 不透明度和 100% 字号。
- **自动检查软件更新**默认开启：正式发布版启动约 10 秒后检查一次，之后最多每 6 小时检查一次。检查只显示新版入口，不会自动下载、安装、重启或抢占对局。关闭后仍可在「关于与更新」手动检查。

发现新版后，浮窗会显示「发现新版本」按钮。进入「关于与更新」后选择“下载更新”，下载完成且通过 GitHub SHA256、大小和版本校验后，仍须由你点击“重启并更新”。
