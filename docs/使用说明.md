# 替身计时器使用说明

纯视觉，不读取游戏进程内存。看 MuMu 画面认场景、豆和账号名，分别跟踪两侧事件，浮窗只显示对面的替身倒计时。

## 日常怎么用

1. 开模拟器，进游戏。
2. 双击 `启动计时器.bat`，或先 `build.bat` 再开 `bin/timer-app.exe`。
3. 主窗口是**悬浮窗**：深青不透明底、青色读秒，避免游戏背景透出干扰数字。没有已确认替身时是 `—`。底下显示当前场景、观测状态和两边豆数。
4. 点「设置」填自己的账号名、选手动边或自动认边、是否置顶。
5. 认错边：点「换边」，或在设置里锁左边/右边。换边后悬浮窗仍只跟对面走。
6. 自动模式会识别 **VS / 死亡换人底栏**和**对局顶部**的账号名，确认我方在左还是右。尚未认出时显示「对面·待认边」，不会把某侧的计时当成对面。
7. 对局采集目标间隔默认 **16ms**，大厅 **400ms**；实际速度取决于截图、分析和系统调度，不承诺固定帧率：
   - 掉 1 颗可用豆 = 放替身。连续确认后开钟，剩余仍按**第一次看到掉豆那一帧**算：`15 − (现在 − 抓帧时刻)`。
   - 界面按 0.1 秒跳一格：`15.0 → 14.9 → … → 0.1`。到点才换字，没有动画。
   - 单帧闪一下 4→3→4 不开钟。有豆没看清、或一侧豆序非法（采偏）也不开钟。
   - 一次掉 4 颗 = 大招，不计时。掉 2/3 忽略。
   - 训练场和决斗场使用不同标定。已识别场景绑定对应布局；缺少绑定时按可信观测选取，避免随闪光乱换采样点。
8. 死亡换人、VS、匹配、选阵容或画面看不清：不凭旧豆确认新事件；未知豆数不冒充当前豆。**已确认的倒计时仍按真实经过时间继续**，回对局重新校准观测。

   已识别的同局换人返回后，若豆数不同于动画前，至少两次有效观测只确认当前豆数，不把跨动画的差值算作替身。核对完成后，本回合实际观察到的掉一豆仍按原确认帧数即时计时，没有额外数秒禁用期。若真正替身发生在不可见的动画/返回校准期间，仅靠两端豆数无法确认，不会编造一次事件。
9. 连续确认回到 **大厅 / 结算** 后清钟；跨训练场/决斗场的布局切换也会重建比赛基线。
10. 训练场未提供可用账号认边证据时，浮窗显示「训练场·请选我方边」。在设置里选自己所在左/右侧即可，不需要改账号或指定忍者。不能用角色名字猜账号归属。

## 设置

点悬浮窗「设置」：

- **我的名字**：填自己的账号名，用来自动认边。多个名字用逗号隔开。
- **指定对面忍者**：留空使用当前画面的名字识别，也可在下拉输入框指定完整版本。**仅「照美冥[五代目水影]」显示 15 秒 / 10 秒两条同起点倒计时**；普通忍者、裸名字「照美冥」和其他版本均按 15 秒。旧解包表和历史 ID 不再决定正式前端或回放器的冷却。
- **我方所在边**：自动认边 / 左边 / 右边，**点选立即生效，不需要点保存**。我方选左，浮窗显示「对面·右」并使用右侧计时；我方选右则相反。手动锁定不会被自动识别覆盖。切回自动会使用近期识别结果，没有结果则等待下一次识别。
- **记住认边方式**：立即保存是否记住。勾选后，下次使用所选模式（自动 / 左 / 右）；取消后，手动选择只在本次生效，下次回到自动。自动识别到某一边不会把自动模式改成手动锁定。
- **窗口置顶**：浮在模拟器上。

名字和对面忍者等字段点「保存」后写入 `config.json`。账号名单在 `ui.playerNames`；VS 模板放在 `assets/identity/`，对局顶部姓名模板放在 `assets/identity/fight/`。模板不是通用 OCR；修改名字后会重新载入模板。现在还可开启「后台识别名字（本机中文 OCR）」补充清晰的账号和忍者文字：两个图像处理结果一致、两次采集结果一致且当前字形未改变后才使用。低清晰度/错字不会用包含匹配硬凑我方账号；缺少模板也不会借用对面名字认边。

## 调试（不猜参数）

只认这两处，不会自己猜：

- `config.json` 里 `"debug": { "enabled": true }`
- 或环境变量 `NARUTO_DEBUG=1`

有控制台的包（`bin/timer-app-debug.exe`）会在 stderr 打：

`[timer] fight=true scene=fight hold=false beads L=4 R=3 side=right leftCD=— rightCD=14.8`

正式 `timer-app.exe` 是无控制台窗口，要看日志请用 debug 包，或：

```bat
set NARUTO_DEBUG=1
bin\timer-app-debug.exe 2>debug\app.log
```

## 读秒为什么会跳 / 没放替身却在倒计时

以前豆数一闪（4→3→4）会被当成放了替身。  
现在：`tracking.minimumConfirmFrames`（默认 2）个独立新观测连续确认掉 1 才开钟，时间戳仍用首帧。新确认的替身会增加事件编号，并显示最新一次15秒倒计时，即使上一条尚未结束；闪烁、重复帧和未知画面不会凑确认票。界面按0.1秒刷新。

## 对面名字

把对面账号图也放进 `assets/identity/`，例如 `宇智波无名.png`。  
VS / 换人时会在**另一侧**底栏匹配。对上就显示；对不上会裁到 `assets/identity/seen/`，你改成真名再挪回来即可。

## 场景怎么判

| 画面 | 配置项 | 计时 |
|---|---|---|
| 决斗场 | `scene.fightScenes` | 采豆、走钟 |
| 大厅、结算、段位入口 | `scene.endScenes` | 连续确认后清钟 |
| VS、死亡换人、匹配、选人 | `scene.holdScenes` | 不确认新事件；已确认倒计时继续 |
| 看不清 / 黑屏 | — | Hold |

模板在 `assets/templates/`，交整张图到 `inbox/` 再筛，不要自己乱裁。

build.bat

## 特殊忍者与五代目水影（2026-09-07 用户确认规则）

- **五代目水影**：设置中选择完整的「照美冥[五代目水影]」并保存。对面每次确认替身后同时显示 15 秒和 10 秒，基于同一次掉豆的首帧时间，只增加一次事件编号。10 秒到点后显示「就绪」，15 秒继续；下一次替身同时重启两条估计。两条是候选时间，不声称程序已辨别本次到底采用哪种。
- 裸名字「照美冥」、泳装等其他版本、旧表中的数字 ID 均不会触发该例外。名字/版本指定只影响对面，不用我方的替身事件开钟。
- 用户提供的柱间[木叶创立]、斑[神驹佑祥]按名字确认六槽；带土[十尾人柱力]与鸣人[暴怒·第六尾]为四槽特殊紫/红配色。左右两侧槽数独立，六槽转四槽只重校观测，不把槽数变化算作替身。
- 原图回归已覆盖这九张裁图的名字与可用豆；全画面串联测试是明确标记的合成拼接，不代表已获得这些特殊忍者的完整实机连续对局录像。
- 本批图没有五代目水影的姓名画面，因此该版本的**双计时规则与手动指定已支持，自动视觉认出该版本尚缺实图校验**。不能把其他版本的头像或裸名字当成五代目水影。

## 后台文字识别（2026-09-07）

- 设置中的「后台识别名字（本机中文 OCR）」默认开启，勾选/取消立即作用于运行中的识别器并保存，不用重启。不会影响模板采豆、手动锁边和手动指定忍者。
- 使用 Windows 已安装的简体中文 OCR，不联网、不上传截图、不修改语言包。系统不支持或受策略限制时会显示不可用，继续使用原有模板/手动选择。
- 文字是辅助证据：我方账号须完整相等且只在一侧出现；完整版本也要经交叉核对。裸名字「照美冥」仍不会启用五代目水影的双计时。
- 已在无姓名模板的测试目录，从原始截图识别出「山中井野（白方小）」并进入实时结果。另一些低分辨率名字仍有错字/不一致，必须保留待识别；不能称为所有账号和忍者均已支持。
- 本批没有五代目水影的自然截图，故其文字解析/手动规则虽已支持，真实视觉识别仍待校验。
- 离线排查可运行 `bin/timer-lab.exe ocr -image inbox/regressions/duel-second-round-20260906.png`。`-out <新文件.json>` 会显式保存包含可见姓名的报告；正常计时不保存这些原始文本。
- `timer-lab observe` 如果没有采到有效画面，会返回失败、延迟为 null，并区分尝试次数和有效帧速率。不要将采集接口故障误读成零延迟。
- 主动关闭 MuMu 时无画面是预期情况；不需要为此修改认边和冷却配置。
- OCR 暂不可用时按5秒间隔退避，切换场景不会反复重启助手。重试会显示当前核对状态；姓名已经消失时不会再显示旧的「已核对」。关闭计时器后，迟到画面不再刷新已关闭的窗口。

## 场景稳定与豆数问号（2026-09-08）

- 已确认的训练场/决斗场不会只因短暂遮挡或一个竞争标签就切换坐标。画面不清时显示原场景及「画面遮挡」，并停止使用不清楚的观测；明确页面仍按大厅/结算/换人处理。
- 一颗豆看不清不再连带抹掉同侧其他可信槽，也不阻止另一侧完整观测确认替身。金豆自身闪光通过固定豆体形状核对，减少白色中心造成的问号。
- 问号表示该侧目前不能得到完整可靠豆数，绝不补成旧豆或猜一个数字。真正大面积遮挡时仍可能显示问号，已确认的倒计时继续；恢复后按原观测连续性规则校准。

### 自审修复补充（2026-09-08）

- 普通饱和黄光也必须通过当前豆体与间隙的对比核验，不能只凭颜色把空豆当作补豆；遮挡未知不投票，光效后的正常掉豆仍按原规则确认。
- 同一场景短暂停顿时，仅保留当前字形仍可验证的已确认名字/账号，最长2秒；恢复后再核验当前像素，不必重做两次OCR。暂停期间不把保留值输出成当前识别，换人/页面/字形改变、尺寸改变、关闭识别或超时仍失效，不沿用上个人物的名字。
- 场景切换的300ms确认不能跨越超过300ms的采集断档；缺帧或非递增时间戳也会中断未确认候选。此限制不延迟同一场景里的正常替身计时。
