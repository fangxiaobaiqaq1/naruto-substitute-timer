> 本报告只覆盖静态截图，未验证豆变化是否触发计时。用户反馈后的阻断复现、连续帧测试及新测试包见 [豆变化链路修复验证](豆变化链路修复验证.md)；不再以本报告的静态通过作为实战验收。

## 修正范围与边界

1. `HUDScale(refW, refH) = min(W/refW, H/refH)`。16:10 平板按宽度缩放，宽屏按高度缩放；HUD 保持贴顶，不按装饰边框把整幅游戏画面裁成 16:9。
2. 两端的豆位置、核心采样大小、忍者名 / 头像、身份模板及非 legacy 场景模板使用同一缩放。Windows OCR 区域也复用修正后的豆排锚点。
3. 宽屏内置标定根据当前画面生命条固定外端的三条连续斜边扫描线求 X 偏移。左右分别计算，不要求对称；仅平移整排，不修改豆间距、Y 坐标、状态阈值或亮豆数量。
4. 缺失、遮挡、平直特效、错误斜率或异常偏移不提供校正，保留原标定；不缓存豆数，不以最亮像素重新定位。显式用户标定不被覆盖，六槽扩展保留已确定的 X 偏移。

这是截图识别回归，不等同于任意设备、任意 UI 调整或整段实战均已验收；低血量 / 特效导致生命条锚点不可确认时仍可能无法完整识别。

## 复现

需 Go 1.26.1；将上述原图保留在仓库根目录：

```bash
go test ./internal/detect ./internal/engine ./internal/engine/rgb ./internal/engine/factory \
  -run 'TestHUD|TestMapHUD|TestLegacyLayout|TestConfiguredLayout|TestSixSlotExpansionKeepsWideHUDOffset|TestUserResolutionSamples' \
  -count=1

bash android/tools/hostcheck.sh
android/build/hostcheck/hostcheck --repo "$PWD" ./图片_*.png > /tmp/resolution-cpp.txt
go run -tags gocheck ./android/tools/gocheck ./图片_*.png > /tmp/resolution-go.txt
diff -u /tmp/resolution-go.txt /tmp/resolution-cpp.txt
```

缺少原图时，`TestUserResolutionSamples` 按图跳过，不能把跳过视为图像验收成功。无图也能运行合成几何及反例检查。

本静态适配阶段的扩展测试并非全绿：一些旧测试依赖未分发的 `inbox/`，当时还存在侠隐坐标单位及红色特效判别相关失败。后续特殊 HUD 修复已校正这些问题，`TestSasukeXiayinRowBothSidesAndLayouts`、`TestXiayinRedRequiresVariantAndRejectsEffects` 已通过；缺失私有截图的旧用例仍不能验证。后续改动与新包见 [豆变化链路修复验证](豆变化链路修复验证.md#后续特殊-hud-与跨比例修复)。

- `dist/resolution-adapt/SHA256SUMS.txt`：上述两个产物的 SHA-256。

未修改正式版本号、未发布更新、未在 Windows 模拟器或 Android 真机安装验收。APK 使用本地调试签名，可能无法覆盖不同签名的已安装正式版；不要为安装测试包贸然卸载而丢失配置。
