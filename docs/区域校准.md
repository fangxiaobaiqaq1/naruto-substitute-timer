# 区域校准（豆与头像）

给少见分辨率/比例（平板、带鱼屏、模拟器奇怪窗口）用：自动布局算错时，玩家在一帧游戏画面上自己框出每一侧的豆和头像，识别改用这些框。Windows 与安卓用同一份定义，行为必须一致（Go 与 C++ 同步）。

## 存储

与自动布局解耦：单独一块，空表示「全部自动」，每个框各自独立（只校准豆、只校准头像、只校准一侧都可以）。

Windows `config.json`：

```json
"layout": {
  "calibration": {
    "profile": "duel",
    "leftBeads":   {"x": 0.081, "y": 0.104, "width": 0.052, "height": 0.022},
    "rightBeads":  {"x": 0.867, "y": 0.104, "width": 0.052, "height": 0.022},
    "leftAvatar":  {"x": 0.004, "y": 0.006, "width": 0.072, "height": 0.128},
    "rightAvatar": {"x": 0.924, "y": 0.006, "width": 0.072, "height": 0.128}
  }
}
```

安卓 `Settings`（SharedPreferences）：`calibProfile`，`calibLeftBeads` / `calibRightBeads` / `calibLeftAvatar` / `calibRightAvatar` 为 `"x,y,w,h"` 字符串，空串 = 未校准。经 JNI 传给原生核心。

- 坐标是相对**整张采集画面**的比例（0–1，左上为原点），与分辨率、采集缩放无关（安卓录屏 1280 宽、无障碍截屏原尺寸都能用）。
- `profile`：框是在哪种布局（`camp` 训练场 / `duel` 决斗场等对局）的画面上画的。另一种布局按同一侧的变换换算，不必再画一次。

## 含义

**豆框**：紧贴这一侧的 4 颗普通豆（第 5、6 颗只有柱间有，不框）。

- 第 i 颗（0 = 最外侧）中心：左侧 `x = rx + (i + 0.5)·rw/4`，右侧 `x = rx + rw − (i + 0.5)·rw/4`；`y = ry + rh/2`（乘画面宽高得像素）。
- 每侧一个相似变换（统一缩放 + 平移），把 `profile` 布局的 1600×900 标称中心映射到上述中心：`s = (rw·W/4) / pitch_P`，`pitch_P = |C3.x − C0.x| / 3`（左侧训练场 25、决斗场 77/3；右侧 76/3、25）；`X = cx0 + s·(Xref − C0.x)`，`Y = cy + s·(Yref − C0.y)`。当前帧是另一种布局时，用同一变换映射那种布局的标称中心。
- 由 `s` 得出这一侧的尺度：豆采样核心 `s·1600/1920`，名字/头像 `s·1600/960`。校准侧不做宽屏 HP 条 x 修正；特殊忍者的整行下移（水门/佐助/鼬能量条）照常 `y += 偏移·s·1600/960`；柱间第 5、6 颗按校准后的像素间距外推。

**头像框**：紧贴这一侧菱形头像框的外接矩形（四个顶点，含细边框；不含名字、血条和伸出框外的头发）。由框的中心和边长换算成头像识别使用的窗口与尺度，使「框贴住头像」时与自动路径在正常分辨率下得到的窗口/尺度一致。另一种布局时，按这一侧第 0 颗豆在两种布局间的位移平移（豆已校准用校准变换，未校准用自动布局）。

- 换算（960 宽参考单位）：边长 `b = (w+h)/2`，尺度 `s = b / 68.5`；窗口左上 = 框中心 − `(42, 49.5)·s`（左侧）/ `(36, 49.5)·s`（右侧），大小 `70s × 100s`（与自动窗口同型）。
- 常数实测自 13 个原生头像（1280×720–2880×1800，训练场与决斗场）：菱形框边长 66.7–71.8（均值 68.4），中心在自动窗口内左 (41.5–42.7, 49–50)、右 (35.1–36.5, 49–50.8)。框画准时换算结果与自动窗口偏差 ≤ 2.2 单位、尺度 −2.7%…+4.7%（+4.7% 是侠隐江湖的金光），认出的头像相同；尺寸偏 5% 或位置偏 2 单位时部分头像会认不出。
- 右侧「百战鼬」的固定头像核对在已校准的右侧改为相对头像窗口：窗口左上 + `(8, 9)·s`，允许 ±2 单位。

未设置的框完全走原来的自动路径，结果逐像素不变。

## 使用

- Windows：设置 → 常规 →「区域校准（豆/头像）」。窗口显示当前采集到的画面（打开时才复制帧，连同这一帧的几何）：
  - 白色虚线是这一帧自动识别实际用的区域：每侧采样的豆心（十字）、名字搜索区（标「名字」）、头像识别窗口（标「头像窗口」），画到画面边缘为止；「显示自动识别区域」可关掉。大厅、结算等没有几何的画面在状态栏注明，只能直接画框。
  - 可编辑的框：没校准的目标以本帧的 `beadBox` / `avatarBox` 为起点，标「（自动）」；已保存的标「（已保存）」，改过还没保存的标「（未保存）」。选 左侧豆 / 右侧豆 / 左侧头像 / 右侧头像（或在框上按一下）后：框里拖动移动，拖边或角调大小，空白处拖动重画；点过画面后方向键微调 1 像素（按住 Shift 调右边、下边）。移动和调大小按整像素，不动的边保持原值（默认框的豆心正好跟着移动）；挪回原处不算改动。豆框上的 4 个小点应落在每颗豆中间。
  - 「保存」只写入改过的框；没有改动时什么都不写，也不通知引擎。保存立即生效（引擎 `SetCalibration`，同一画面也会重新分析）：原画面的虚线与默认框作废，窗口换上按新设置分析的下一帧（正在改框、或新画面没有几何时保留原画面）。「清除所选」「全部恢复自动」恢复自动识别。
  - 「导出方案」把要保存的框（已保存的加上未保存的改动，不含没动过的默认框）写成方案文件，默认文件名 `校准方案-2400x1080.json`（当前画面大小）。「导入方案」检查 `kind`/`version`/框的范围，画面比例相差超过 2% 时提醒，再把文件里的框作为未保存的改动放进编辑器（布局取文件的 `profile`；文件里没有的已保存框会清除），检查后按「保存」生效。
- 安卓：游戏里点计时卡片 → 设置 → 位置 →「区域校准」，面板关闭后自动截下一帧游戏画面，连同这一帧的几何（同一次分析的 `NativeCore.lastGeometry`，和画面一起存在缓存里，旋转、进程重建后照常）打开编辑页：
  - 白色虚线是这一帧自动识别实际用的区域：每侧采样的豆心（十字）、名字搜索区（标「名字」）、头像识别窗口（标「头像窗口」），画到画面边缘为止；「显示自动识别区域」可关掉。大厅、结算等没有几何的帧和载入的截图在面板里注明，只能直接画框（截图不送进正在运行的识别管线，免得打乱它的状态）。
  - 可编辑的框：没校准的目标以本帧的 `beadBox` / `avatarBox` 为起点，标「（自动）」；已校准的显示已保存的框（它们在这一帧上没有自动位置，恢复自动后重新取一帧才看得到）。拖动画框、拖边角微调、双指缩放、双击放大；挪回原处不算改动。区域卡片标出 自动 / 已校准 / 已修改 / 将恢复自动。
  - 「保存」只写入改过的框（布局只在有新框且不同时写）；没有改动时什么都不写，识别一切照旧。保存立即生效（`nativeSetCalibration` 重建识别管线）；「清除所选」「全部恢复自动」恢复自动识别。
  - 「导出方案」「导入方案」用系统文件选择器，规则同 Windows：导出要保存的框（不含没动过的默认框），默认文件名 `校准方案-2400x1080.json`；导入检查 `kind`/`version`/框的范围，比例相差超过 2% 或布局与这一帧不同时提醒，有未保存的改动先确认，再整套替换为未保存的改动（文件里的框按原值保存，文件里没有的已保存框标「将恢复自动」），检查后按「保存」生效。
  - 主界面 → 高级设置 →「区域校准」可查看状态、恢复自动或载入一张截图来画。
- 在对局或训练场画面上校准。分辨率特殊时程序可能认不出这是对局：这时手动选「训练场 / 决斗场」再画（载入的截图也要手动选）。
- 豆框画在普通忍者的豆行上：九喇嘛水门、侠隐佐助、百战鼬的豆行本身已下移，在它们身上框会与识别时的整行下移叠加。
- 头像框要贴紧（误差约 ±5%、2 个单位以内），太大太小会认不出忍者。

## 显示自动结果、默认方案与导入导出

校准界面先把**识别实际用的区域**画在这一帧上，玩家据此判断要不要改；没改的框保持自动，一切照旧。

### 每帧几何（引擎报告，Go 与 C++ 数值一致）

每一侧（左、右）：

- `beads`：本帧实际采样的豆心（像素，含特殊忍者整行下移、能量条重读与柱间第 5/6 颗）。
- `nameRoi`：名字（标题模板）搜索区（像素；Windows 的 OCR 条带另算，不在此列）。
- `avatarRoi`：头像识别窗口（像素）。两个区域都不裁剪到画面内（头像窗口常伸出顶边），识别时才裁剪。
- `beadBox`：默认豆框（整帧比例）：由**下移前**的 4 颗布局豆心得出，`x` 从第一颗豆心左侧半个间距到最后一颗右侧半个间距，宽 = 4 个间距，高 = 1 个间距，竖直中心为豆心所在行。拿它直接保存，得到的豆心与自动完全一致。
  - 用未取整的豆心与尺度 `s`（校准侧为校准尺度），含宽屏 HP 条 x 修正；某颗豆离取整边界不足 0.001 像素时（如正好在半像素上）把框微调到 0.001 像素以外，安卓 float32 存储后仍一致。
  - 例外：自动豆心把同一行的两个半像素平局取整到相反方向时没有精确框（如训练场左侧在 1440×900、2400×1350，尺度 0.9、1.5）：第 0 颗（名字/头像的锚点）仍一致，其它豆可能差 1 像素。
- `avatarBox`：默认头像框（整帧比例）：`avatarRoi` 按上面「头像框」的换算反推（边长 `68.5·s`，窗口原点取其取整区间的中点）。拿它保存，头像窗口与尺度与自动一致；只有 `38·s`、`62·s` 同为半像素平局的尺度（1.25、1.75…）窗口会矮 1 像素（左上角不变）。

大厅/结算等不采豆的帧、不支持的分辨率与 OpenCV 引擎没有几何（零值）。

- Windows：`frame.Frame.Geometry`（`[2]frame.SideGeometry`，0 左 1 右，即 `engine.Result.Geometry`），去重复用的帧带着被复用分析的几何。
- 安卓：`NativeCore.lastGeometry(): FrameGeometry?`，最近一次分析（含去重复用）的帧，整帧一起取；`sequence` 对上 `AnalysisResult.sequence`。扁平布局见 `android/ARCHITECTURE.md` §4 `nativeLastGeometry`。

### 默认方案

打开校准时，四个可编辑框的初始位置 = 本帧的 `beadBox` / `avatarBox`（已校准的框显示已保存的值）。只有玩家动过的框才会保存；没动过的仍是自动（不写入配置）。

### 方案文件（导出 / 导入，Windows 与安卓通用）

```json
{
  "kind": "naruto-timer-calibration",
  "version": 1,
  "frameWidth": 2400,
  "frameHeight": 1080,
  "profile": "duel",
  "leftBeads": {"x": 0.081, "y": 0.104, "width": 0.052, "height": 0.022},
  "rightAvatar": {"x": 0.924, "y": 0.006, "width": 0.072, "height": 0.128}
}
```

- 只含已校准的框（缺省 = 自动）；`frameWidth/Height` 只作提示：导入时与当前画面比例相差超过 2% 要提醒，可能不准。
- 导入只放进编辑器，玩家看过后再「保存」；`kind`/`version` 不对或框越界拒绝导入。
