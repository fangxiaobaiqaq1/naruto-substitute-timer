# Android 原生版开发与发布

本文说明 `android/` 子项目的开发、调试、发布和故障排查。Android 版是在模拟器内部运行的原生应用，不依赖 Windows 端 Fyne 界面，也不需要 root。

> 当前 Android 版本暂定为 **v2.9.0 / versionCode 29**；下一次正式迭代目标为 **v2.10**。版本号只在 `android/app/build.gradle.kts` 中维护。

## 1. 目标与范围

Android 版完成以下工作：

- 在雷电、MuMu 等 Android 12+ 模拟器内部运行；
- 使用 MediaProjection 获取高帧率画面；
- 使用 AccessibilityService 承载原生悬浮窗，并作为低帧率截图兜底；
- 复用仓库中经过调参的像素、模板、场景和忍者识别算法；
- 使用 C++17 NDK 执行识别热点，Kotlin 负责 Android 生命周期、采集、计时状态和显示；
- 悬浮窗与 Windows 端 UI 解耦：Android 只显示紧凑状态条和原生操作栏。

Android 端不读取游戏内存、不注入游戏、不需要 root，也不申请 `SYSTEM_ALERT_WINDOW`。识别输入是屏幕像素。

## 2. 技术栈与目录

| 项目 | 当前值 |
|---|---|
| UI / Android 生命周期 | Kotlin + Android Framework API |
| 识别核心 | C++17 NDK，通过 JNI 调用 |
| 计时与跟踪 | Kotlin，移植 `internal/app/timer.go` 和 `internal/ui/run.go` 的状态逻辑 |
| 最低版本 | Android API 31 |
| 编译 / 目标版本 | compileSdk 35 / targetSdk 34 |
| ABI | `x86_64`、`arm64-v8a` |
| 包名 | `com.narutotimer` |

主要目录：

```text
android/
  app/src/main/java/com/narutotimer/
    capture/       MediaProjection、ImageReader、无障碍截图、分析线程
    overlay/       Android 原生 Canvas 悬浮状态条和操作栏
    service/       AccessibilityService 生命周期
    tracker/       SideClock、Session、自动/手动认边
    update/        GitHub/Gitee 检查、SHA256 校验、APK 安装
    ui/            手机端主界面、权限指引、设置
  app/src/main/cpp/
    jni.cpp        NativeCore JNI 边界
    include/nt/    C++ 公共接口
    src/           match、detect、scene、rgb、ninja、identity、frame
  ARCHITECTURE.md  模块契约、线程模型、JNI 编码和资源映射
```

`android/ARCHITECTURE.md` 是模块接口的权威文档；修改共享头文件、`NativeCore.kt` 或 `AnalysisResult` 前必须先更新契约。

## 4. 构建与检查

进入 Android 项目：

```bash
cd android
printf 'sdk.dir=%s/Android/Sdk\n' "$HOME" > local.properties
```

编译 Kotlin：

```bash
$GRADLE :app:compileDebugKotlin --offline
```

构建 Debug APK（包含 x86_64 和 arm64-v8a）：

```bash
$GRADLE :app:assembleDebug --offline
```

产物：

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

检查 C++ 语法：

```bash
find app/src/main/cpp/src -name '*.cpp' -print0 |
  xargs -0 g++ -std=c++17 -O2 -Wall -Wextra -fsyntax-only \
    -I app/src/main/cpp/include
```

构建 host recognition smoke check：

```bash
./tools/hostcheck.sh
```

hostcheck 只验证资源加载、C++ 链接和可运行性；没有真实训练场截图时，不能代替模拟器验收。

## 5. Android 运行架构

### 5.1 启动顺序

1. `TimerApp.onCreate()` 创建 `Settings` 和 `Session`；
2. 后台线程通过 `AssetLoader` 加载模板、头像、忍者资源和 JSON；
3. `NativeCore.nativeFinishAssets()` 构建 C++ 引擎；
4. 用户在系统设置中开启 `TimerAccessibilityService`；
5. 无障碍服务连接后**只建立连接，不自动显示悬浮窗**；
6. 用户在主界面点击“启动悬浮窗”后，才创建 overlay、启动 `FrameLoop` 和截图兜底；
7. 用户可单独授权 MediaProjection；它与悬浮窗启停分离。

`Settings.overlayEnabled` 是持久化的用户意图，但服务连接不会无条件恢复旧窗口。所有启动、停止、重启操作都是幂等的。

### 5.2 采集与识别链路

```text
MediaProjection
  -> VirtualDisplay
  -> ImageReader RGBA_8888
  -> acquireLatestImage()
  -> HardwareBuffer
  -> FrameLoop 单槽 latest-frame-wins
  -> NativeCore JNI
  -> C++ scene/rgb/ninja/identity
  -> AnalysisResult
  -> Session
  -> OverlayState
  -> Canvas View
```

备用链路：

```text
AccessibilityService.takeScreenshot()（系统限速，约 3 fps）
  -> HardwareBuffer / Bitmap fallback
  -> FrameLoop
```

采集回调必须及时 `close Image` 和 `close HardwareBuffer`。重建或 resize `ImageReader` 时使用 generation 丢弃旧 reader 的回调，避免读到已关闭的 buffer。

### 5.3 线程

- Android 主线程：WindowManager、悬浮窗位置、Activity 和设置控件；
- capture HandlerThread：ImageReader 回调；
- `nt-analysis`：单一 C++ 分析线程；只保留最新帧，不排队；
- Kotlin Session 锁：保护采集线程和主线程之间的状态；
- 主线程按计时器边界刷新 Canvas，不在 UI 线程做识别或网络。

## 6. 悬浮窗交互与生命周期

### 6.1 显示态

游戏画面上默认只显示紧凑状态条：

```text
替身计时·自动·左：等待决斗
替身计时·左：14.8
替身计时·右：—
```

其中：

- `自动`：设置选择“自动认边”，但还没有识别出左右；
- `自动·左` / `自动·右`：自动识别已经确定我方位置；
- `左` / `右`：用户手动锁定的一侧；
- “等待决斗”表示当前没有有效对局倒计时，不代表识别线程一定停止。

收起状态条不显示桌面式大面板，也不保留永久拖动小托。

### 6.2 操作态

点击状态条显示紧凑操作栏：

```text
换边  设置  两边计时  退出
```

“退出”是实际的 `stopOverlay()`，会隐藏悬浮窗、停止分析线程和无障碍截图；不会自动撤销 MediaProjection 授权。再次使用必须点击主界面的“启动悬浮窗”。

### 6.3 任意位置

悬浮窗位置不自动吸附左右边缘：

- “调整显示位置”进入临时拖动模式；
- 松手保留精确 `x/y`；
- 只限制不能完全拖出安全显示区域；
- 位置保存在 `Settings.overlayX/overlayY`；
- 状态显示和设置页面彼此独立。

### 6.4 大小与透明度

主界面的“悬浮窗大小”控制整体缩放，范围约为 55%–120%，默认 75%；它影响 Canvas 布局和文字，而非只改变字体。完整模式和迷你模式有独立透明度设置。透明度修改通过 Settings listener 实时更新卡片和交互区域。

## 7. 权限

### 无障碍服务

用途：

- `TYPE_ACCESSIBILITY_OVERLAY` 原生悬浮窗；
- `takeScreenshot()` 低帧率备用采集。

不读取游戏节点文本，`canRetrieveWindowContent=false`。无需 `SYSTEM_ALERT_WINDOW`，也不需要 root。

### MediaProjection

用途：推荐的高帧率采集路径。第一次使用需要系统录屏授权；用户可以选择“共享一个应用”。Android 14+ 必须遵守：

```text
授权结果 -> startForeground(mediaProjection) -> getMediaProjection
-> registerCallback -> createVirtualDisplay
```

MediaProjection 与悬浮窗是两个独立开关。停止悬浮窗不会强制停止用户正在使用的录屏服务，避免下次重复弹授权。

### 安装未知来源

在线更新使用系统 APK 安装器。Android 8+ 可能需要允许本应用“安装未知应用”；应用会跳转到对应设置页，绝不静默安装。

## 8. Android 在线更新

设置中可以选择：

- Gitee（国内）：`xiaobaiqaq/naruto-substitute-timer`；
- GitHub（海外）：`fangxiaobaiqaq1/naruto-substitute-timer`。

更新器只接受 HTTPS 和严格 host allowlist，限制响应 2 MiB、APK 256 MiB，下载到临时文件后校验 SHA-256，再通过 `UpdateFileProvider` 交给系统安装器。

每个 Release 推荐上传：

```text
naruto-timer-universal.apk
SHA256SUMS.txt
```

校验文件：

```text
<64位小写SHA256>  naruto-timer-universal.apk
```

GitHub 也支持读取 Asset 的 `digest` 字段。缺少摘要、版本号非法、不是正式 Release 或校验失败都会拒绝安装。

## 9. Tailscale / Windows 主机测试

开发机和 Windows 主机加入同一个 Tailscale 网络即可，不需要公网端口映射。当前历史测试方式是 Windows ADB Server 只向 Linux Tailscale IP 开放 TCP 5037：

```bash
adb -H <Windows-Tailscale-IP> -P 5037 devices -l
adb -H <Windows-Tailscale-IP> -P 5037 install -r app-debug.apk
adb -H <Windows-Tailscale-IP> -P 5037 logcat
```

Windows 防火墙应将远端地址限制为开发机的 Tailscale IP；不要把 ADB 5037 或模拟器 5555 暴露到公网。

## 10. 故障排查

### 重启后系统显示“此服务出现故障”

先确认包没有被系统标记为 stopped：

1. 打开计时器主界面一次；
2. 进入系统“无障碍”详情页；
3. 关闭计时器无障碍，再重新开启；
4. 回到应用，点击“启动悬浮窗”。

不要在服务尚未连接时重复点击录屏授权。若只是停止悬浮窗，使用应用内“启动/停止/重启悬浮窗”，不要用系统“强制停止”。

### 无障碍已开但悬浮窗不见

主界面状态应区分：

```text
无障碍已连接 / 悬浮窗未启动
无障碍已连接 / 悬浮窗运行中
无障碍已开启但正在连接
```

点击“重启悬浮窗”。若仍无效，关闭再开启无障碍服务；应用启动时会等待 `TimerApp` 初始化后重试，不应因启动竞态被系统标记为故障。

### ImageReader 警告

`Unable to acquire a buffer item` 表示采集背压，通常与模拟器渲染模式、resize 或旧 Image 未及时释放有关。检查是否使用最新版本；代码会使用 `acquireLatestImage`、generation 和 finally 释放。若出现黑帧，可切换模拟器 DirectX/OpenGL 渲染模式，并重新授权共享应用。

### 识别一直显示“等待决斗”

确认：

- 悬浮窗已启动，不只是无障碍已连接；
- MediaProjection 已授权，或无障碍截图正在运行；
- 状态页“识别”帧数在增加；
- 设置的认边模式是自动、左、右中的预期值；
- 游戏已经进入支持的决斗场景。

## 11. 版本发布检查

修改版本号：

```kotlin
// android/app/build.gradle.kts
versionCode = 30
versionName = "2.10.0"
```

发布前至少执行：

```bash
export JAVA_HOME="$HOME/.local/opt/jdk-17.0.20.1+1"
export ANDROID_HOME="$HOME/Android/Sdk"
$HOME/.local/opt/gradle-8.11.1/bin/gradle \
  -p android :app:assembleDebug --offline
```

验收项目：

- Kotlin、C++ 和 APK 构建成功；
- x86_64 MuMu/雷电安装成功；
- 开启无障碍后不会自动弹悬浮窗；
- 启动、停止、重启、退出状态互不混淆；
- 重启模拟器后服务不会因初始化竞态崩溃；
- 自动认边、左边、右边文案和计时方向正确；
- MediaProjection 单应用共享和 resize 正常；
- 更新源、APK SHA-256 和系统安装流程可用；
- 发布 APK 同时生成 SHA256SUMS.txt。

Android 版本目前以 Debug 签名构建，正式分发前应配置正式签名、稳定的 `versionCode`，并在 Gitee/GitHub Release 上传对应 ABI/通用 APK 与校验文件。
