# 后端审计（v0.25）

审计基线 `cbfd3fc`（分支 v0.25）。审计记录与复现脚本在仓库外的 `/ssd/work/audit/*.md`；本文汇总结论、修复提交和未完成项。哈希均为合并到 v0.25 之后的提交。

## 范围与方法

范围：除 UI 绘制以外的全部后端——Go `internal/**`（UI 只作为调用方）、`cmd/**`、构建与发布脚本、安卓 C++ 识别核心与 JNI、安卓 Kotlin 非 UI 部分（采集、服务、tracker、NativeCore、AssetLoader、Settings、更新、清单）。

四条审计线（发现编号前缀）：

| 线 | 内容 |
|---|---|
| GE | Go 引擎与后端逻辑：采集、引擎、计时器 SideClock、身份、诊断、配置、支持包 |
| AND | 安卓应用非 UI：Session/SideClock、采集与服务、资源加载、设置、清单 |
| NC | 安卓 C++ 识别核心与 JNI 边界 |
| UR | 在线更新、发布流程与供应链、雷电接入 |

工具与方法：

- `govulncheck`（Windows 与 Linux 构建）、`staticcheck`、`go test -race`（含审计专用的并发探针测试）。
- C++：ASan/UBSan（含 float-cast-overflow）、TSan、`-O3` 对照；线程池故障注入（`bad_alloc`、`pthread_create` 失败）。
- 伪 JNIEnv/JavaVM/AHardwareBuffer 夹具：在主机上编译真实 `jni.cpp`，做边界、模糊、并发、退出竞争和内存测试（现为 `android/app/src/main/cpp/tests/jni_host_test.sh`）。
- Go 与 Kotlin 对照：`android/tools/clockcheck`（SideClock）、`sessioncheck`（Session ↔ Go `captureOnce`）、`limitscheck`（校准框限制，Go/C++/Kotlin 同一摘要）；`appcheck` 是 Kotlin 逻辑的主机检查。
- 识别一致性语料 `/ssd/work/perf-corpus`：`run-parity.sh go|cpp` 的输出必须与 `golden-go.txt` / `golden-cpp.txt` 逐字节相同（含 194 个校准用例）。

修复分五组并行（T1 计时与 Go 健壮性、T2 安卓 Session 对齐、T3 安卓采集/服务/更新、T4 原生核心与校准限制、T5 更新/发布/供应链/隐私），按 T4 → T1 → T5 → T2 → T3 拣选到 v0.25；合并后的补充提交：`4862755`（sessioncheck 适配合并后的树）、`79d47ba`（安卓 Session 跟上 GE-02/GE-09）、`45b8448`（旧配置里超限的校准框启动时去掉而不是报错）、`60e97c5`（chaincheck 跟上 GE-02）。

## 留给维护者决定

- **UR-01 签名的发布清单**：用离线 Ed25519 密钥签名 `release-manifest.json`，客户端内置公钥校验。密钥由谁保管、在哪里签名需要维护者决定；方案见 `docs/更新签名设计.md`，代码与流程都未改。
- **UR-05 版本命名**：不要再发两段式标签（v0.25）；建议下一版用 `v0.3.0`。未设置 `TIMER_VERSION` 的安卓构建 versionName 是 `0.2.10`（本次调试 APK 也是）。
- **安卓 14+ 采集分辨率**：录屏现在开始时总是横屏 1280 宽（AND-01），14+ 之后仍跟随 `onCapturedContentResize` 变为原生分辨率（性能文档遗留 1），是否限制长边 ≤1280 待定。
- **versionCode 每次发版必须递增**：`0d63336` 起应用内更新拒绝 versionCode 不高于当前的 APK；`build.gradle.kts` 里仍固定为 30，最近几版都是 30。
