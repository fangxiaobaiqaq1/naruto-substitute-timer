# 开发与发布

## 构建

### Windows 原生（发布和运行验收路径）

需要 Windows x64、**Go 1.26.1**、Windows PowerShell（`powershell.exe`）和 Fyne 所需的 x64 C/C++ 工具链。使用 MSYS2 MinGW-w64 时，从其 x64 UCRT64 shell 启动 PowerShell，或确保 `gcc`/`pkg-config`/Windows SDK 库在 `PATH` 中；使用 Visual Studio 时从 x64 Developer PowerShell 启动。必须保持 `CGO_ENABLED=1`，不能以 `CGO_ENABLED=0` 跳过 Fyne 原生渲染器。

从仓库根目录执行：

```powershell
$env:TIMER_VERSION = 'development' # 发布时替换为实际版本
$env:CGO_ENABLED = '1'
.\build.bat
if ($LASTEXITCODE -ne 0) { throw 'build.bat failed' }
```

`build.bat` 先下载模块，再调用 `scripts\fyne-diagnostics\prepare.ps1`。该脚本只支持未 replace 的 `fyne.io/fyne/v2 v2.6.3`：在 `bin\fyne-diagnostics\` 建立指向 Go 模块缓存的目录 junction，写出 `diagnostics.mod`、`diagnostics.sum`、生成的补丁源和 `overlay.json`，但不修改模块缓存或项目的 `go.mod`/`go.sum`。随后第 3 步以该 modfile 和 overlay 生成 GUI 子系统为 cgo 的 `bin\timer-app.exe`。若 PowerShell 或 cgo 工具链缺失，应补齐它们，而不是更改 build tags 或禁用 cgo。

五个输出：正式前端 `bin\timer-app.exe`、调试前端 `bin\timer-app-debug.exe`、CLI `bin\timer.exe`、校准 `bin\timer-gui.exe`、诊断 `bin\timer-lab.exe`。正式版使用 [绘制回调补丁](../scripts/fyne-diagnostics/README.md)。

### Linux x64 交叉编译（只验证 PE 生成）

Linux 不是 Windows 运行验收环境，但可使用 cgo 交叉构建 PE 文件。已验证的组合是 Go **1.26.1** 与 [llvm-mingw UCRT 20260922](https://github.com/mstorsjo/llvm-mingw/releases/tag/20260922) 的 `x86_64-w64-mingw32-gcc`；该发行包包含 Windows/OpenGL headers 和 import libraries。不要用 `CGO_ENABLED=0`。

```bash
# 在仓库根目录；GO、CC 指向已校验的用户级安装，无需 sudo。
export GO=/opt/go1.26.1/bin/go
export CC=/opt/llvm-mingw-20260922-ucrt/bin/x86_64-w64-mingw32-gcc
export GOOS=windows GOARCH=amd64 CGO_ENABLED=1
scripts/fyne-diagnostics/prepare-linux.sh bin/fyne-diagnostics-linux
"$GO" build \
  -modfile bin/fyne-diagnostics-linux/diagnostics.mod \
  -overlay bin/fyne-diagnostics-linux/overlay.json \
  -ldflags '-X narutotimer/internal/buildinfo.Version=development -H windowsgui' \
  -o dist/timer-app.exe ./cmd/timer-app
file dist/timer-app.exe
sha256sum dist/timer-app.exe
```

`prepare-linux.sh` 是 `prepare.ps1` 的等价实现：同样核对 Fyne v2.6.3 和三个唯一补丁锚点，生成同一 overlay 输入；Linux 以 symlink 代替 Windows junction。交叉构建成功只证明当前源码、overlay、Go 和 cgo 链接器可生成 x64 PE，**不**证明 Fyne/OpenGL、DPI、MuMu SDK、雷电、模拟器或识别功能已在 Windows 运行。仍须按 Windows 原生步骤和 [Windows/MuMu 验收清单](windows-mumu-acceptance.md) 验收。

## 检查

```powershell
go test ./internal/updates ./internal/config ./internal/capture/mumu ./internal/frame ./cmd/timer-app
go test ./internal/scene -run 'TestExpanded|TestDefaultManifest|TestExplicitCustom|TestStandalone'
go test ./internal/ui -run 'TestAboutAndCapture|TestSettingsSide|TestOverlayRender'
```

完整 `go test ./...` 包含未分发的历史截图/个人配置回归；本地有证据时再运行。不要将用户原图或配置为了使测试通过而提交到仓库。

### Linux 主机上的 Windows 测试机

在 Linux 主机（KVM）上跑一台 Windows 10 Enterprise LTSC 评估版虚拟机，只做原生 `build.bat`、`go test` 和打开 timer-app 界面看一眼；MuMu/雷电的验收仍在真 Windows 机上按 [Windows/MuMu 验收清单](windows-mumu-acceptance.md) 做。预算 4 vCPU / 8 GB / 80 GB，不自启，用时手动开：

```bash
mkdir -p /ssd/vm && cd /ssd/vm
curl -fL --noproxy '*' -o win10-ltsc-eval.iso 'https://go.microsoft.com/fwlink/p/?LinkID=2195404&clcid=0x409&culture=en-us&country=US'
virt-install --connect qemu:///system --name naruto-win10 --osinfo win10 \
  --vcpus 4 --memory 8192 --cpu host-passthrough --boot uefi \
  --cdrom /ssd/vm/win10-ltsc-eval.iso \
  --disk path=/ssd/vm/naruto-win10.qcow2,size=80,format=qcow2,bus=sata \
  --network network=default,model=e1000e \
  --graphics spice,listen=127.0.0.1 --video qxl --noautoconsole
virt-viewer -c qemu:///system naruto-win10   # 安装向导；错过“Press any key”就 virsh reset 后连按回车
virsh -c qemu:///system start|shutdown naruto-win10
```

- SATA/e1000e 用 Windows 自带驱动，省掉 virtio-win ISO；IO 够跑测试。
- 来宾内代理填 `http://192.168.122.1:13302`（主机 mihomo），再装 Go 1.26.1 和 MSYS2 UCRT64（cgo）。
- 虚拟机没有 GPU，Windows 只给 OpenGL 1.1，Fyne 要 2.1+：从 [mesa-dist-win](https://github.com/pal1000/mesa-dist-win/releases)（已验 26.2.3 `release-msvc.7z`）取 `x64\opengl32.dll` 放到 `bin\timer-app.exe` 旁边即可打开界面；只看布局和交互，帧率不代表真机。
- 全量 `go test ./...` 需把本机 `inbox/` 与 `config.json` 拷入；评估版 90 天，`slmgr /rearm` 可续。

## Setup

使用 Inno Setup 6。安装脚本在 `scripts/installer/`；编译器不提交到仓库。设置 `INNO_ISCC` 为 ISCC.exe 路径，并准备包含 timer-app.exe 和 licenses/ 的发布目录：

```powershell
.\scripts\installer\build.ps1 -Version v0.2.4 -ReleaseDirectory F:\release
```

安装为当前用户，不提权；程序目录包含 installed.marker，运行数据位于用户AppData。升级不覆盖配置，卸载不删除个人数据。上游安装语言文件说明见脚本目录README。

## GitHub 发布约定

先创建tag和草稿release，再上传 EXE、Setup、完整ZIP与 SHA256SUMS.txt，核对远端 digest 后公开。更新接口读取本仓库最新正式版和最近100条release；忽略草稿/预发布。每个可在线更新版本必须有名为 `timer-app.exe` 的附件和GitHub提供的SHA256 digest。

发布日志以GitHub `published_at` 为日期来源，正文在页面内按文本呈现，不加载远程图片或执行HTML。更新EXE需要版本自检、完整大小与SHA256校验；只有用户点击重启后才执行替换。
