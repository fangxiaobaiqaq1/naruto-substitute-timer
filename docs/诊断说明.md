# 诊断说明

先在「关于」确认版本，再在「设置 → 模拟器」确认“安装目录 + 实例编号”。实例 `0`、`1`、`2` 是 MuMu 多开编号，不等于 Windows PID；两个 MuMu 安装目录可各自拥有实例 `0`。反馈 SDK、截图或多开问题时，优先导出支持诊断 ZIP 并发送到 BUG 反馈 QQ 群：**1109044204**。

## 采集与延迟

浮窗「诊断」显示当前采集状态、OCR错误及报告入口。开始诊断后记录采集、分析、事件确认、UI投递和绘制提交各阶段。 “验证 MuMu SDK”会在独立进程中检查安装目录、截图 SDK、实例连接和一帧截图；“导出支持诊断包（ZIP）”会汇总实际配置、MuMu 安装目录、实例号、PID、SDK DLL、SDK 阶段结果及现有会话日志。

完整端到端样本必须有同一有效帧的真实绘制提交记录；无帧、重复帧、迟到帧或未完成绘制不能冒充端到端延迟。报告包含 P50/P95/P99。采集接口耗时和分析耗时单列，回放/CLI探针不会报告未测量的屏幕延迟。

## 原帧录制

需要在诊断页手动开启。只有当前成功采集、确认为对局且未保持旧结果的帧才保存；进入对局开始，离开暂停。大厅、选人、结算和未知画面不持续存图片。

无损 PNG 原帧是单独的高体积选项，默认关闭；它会保留采集尺寸，因此长时间对局可能很快接近 1GiB（完整原帧最多768MiB，HUD区域证据最多256MiB）。达到容量或队列上限会记录丢弃原因。原帧保持采集尺寸，不缩放、不添加框；识别、事件和阶段时间通过帧编号关联。普通“诊断回放”不会自动开启 PNG 原帧录制。

## 停止前 3 分钟诊断回放

诊断页可单独勾选「保留停止前 3 分钟诊断回放」。它只对**本次**诊断有效，重启应用不会自动启用，也不会启用无损 PNG。开启后最多每秒（1fps）取一张有效截图，后台缩放至最大宽度 720px 并以 JPEG 质量 75 写入会话目录的 `replay/`，总上限64MiB；这是有界采样回放，不是每个原始帧，更不是无损 PNG，也不会每次实时采集都编码。大厅、保持旧结果和不确定画面可以作为诊断上下文保存；空图或采集错误不会保存。

点击「停止并生成报告」时会固定停止切点，已在切点前接收的回放工作会完成写入，切点后的帧不会进入回放。最终保留切点前最后 180 秒；诊断不足 3 分钟时保留全部已有历史，并在 `replay/manifest.json` 标注 `partial_history`。回放磁盘上限为 64MiB，队列满、写入失败或容量滚动淘汰都会在清单和报告中计数；`.partial` 临时文件不会被列入清单。

回放与原帧 PNG 都会留在本地会话报告目录，即使不导出 ZIP 也会生成。每个回放条目保留原始游戏 JPEG：`replay/<frame_id>.jpg`，并生成同一个 `frame_id` 的标注 JPEG：`replay/annotated/<frame_id>.jpg`。标注图显示帧号、采集时间、停止前偏移、左右忍者/候选、敌我边、槽位和豆状态，以及该帧实际准备的计时器文字、事件次数与 UI prepared/applied/drawn 时间；没有可靠同帧值时会明确标注“当前帧不可用”，不会用后续 UI 或旧帧数据填充。`replay/manifest.json`（schema v2）记录 raw/annotated 路径和对应同帧状态。原图与标注图共用 64MiB 上限，未完整生成的一对图片不会写入清单。可点击「导出诊断回放」生成只包含原图、标注图和轻量清单的小型 ZIP（受64MiB上限约束），无需导出支持包；导出完成后可直接点击「打开文件夹」。

支持诊断 ZIP 默认只包含报告和日志，不含任何游戏图像；只有在诊断页明确勾选「导出 ZIP 时包含原帧/回放图像」才会打包图像。发送 ZIP 前请确认其中图像符合你的隐私预期。

## OCR 与更新问题

- 「打开 OCR 启动日志」：最后失败与最新成功两个有界JSON，包含版本、Windows错误码和原生库路径；不含图像。
- 更新失败：在 `%LOCALAPPDATA%\naruto-timer\updates\last-update.json` 查看最近安装结果。未校验的下载不会安装。
- 场景未识别：请提供游戏区域原图。包含桌面和其他窗口的拼接图不能直接当作原始采集帧。
- 自定义场景清单：默认使用EXE内置资源。自定义请另存为独立文件并设置 `scene.manifest` 路径。
