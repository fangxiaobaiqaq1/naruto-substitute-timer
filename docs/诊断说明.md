# 诊断说明

先在「关于」确认版本，再在「设置 → 模拟器」确认“安装目录 + 实例编号”。实例 `0`、`1`、`2` 是 MuMu 多开编号，不等于 Windows PID；两个 MuMu 安装目录可各自拥有实例 `0`。反馈 SDK、截图或多开问题时，优先导出支持诊断 ZIP 并发送到 BUG 反馈 QQ 群：**1109044204**。

## 采集与延迟

浮窗「诊断」显示当前采集状态、OCR错误及报告入口。开始诊断后记录采集、分析、事件确认、UI投递和绘制提交各阶段。 “验证 MuMu SDK”会在独立进程中检查安装目录、截图 SDK、实例连接和一帧截图；“导出支持诊断包（ZIP）”会汇总实际配置、MuMu 安装目录、实例号、PID、SDK DLL、SDK 阶段结果及现有会话日志。

完整端到端样本必须有同一有效帧的真实绘制提交记录；无帧、重复帧、迟到帧或未完成绘制不能冒充端到端延迟。报告包含 P50/P95/P99。采集接口耗时和分析耗时单列，回放/CLI探针不会报告未测量的屏幕延迟。

## 原帧录制

需要在诊断页手动开启。只有当前成功采集、确认为对局且未保持旧结果的帧才保存；进入对局开始，离开暂停。大厅、选人、结算和未知画面不持续存图片。

默认最多1 GiB：完整原帧768 MiB，HUD区域证据256 MiB。达到容量或队列上限会记录丢弃原因。原帧保持采集尺寸，不缩放、不添加框；识别、事件和阶段时间通过帧编号关联。

## OCR 与更新问题

- 「打开 OCR 启动日志」：最后失败与最新成功两个有界JSON，包含版本、Windows错误码和原生库路径；不含图像。
- 更新失败：在 `%LOCALAPPDATA%\naruto-timer\updates\last-update.json` 查看最近安装结果。未校验的下载不会安装。
- 场景未识别：请提供游戏区域原图。包含桌面和其他窗口的拼接图不能直接当作原始采集帧。
- 自定义场景清单：默认使用EXE内置资源。自定义请另存为独立文件并设置 `scene.manifest` 路径。
