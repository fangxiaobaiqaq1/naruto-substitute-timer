# 后台 HUD 文字识别

这是对精确模板的补充，不是新的场景或豆数检测器。只在引擎已确认的对局画面读取顶部姓名条。

## 忍者表匹配与前端状态（2026-09-07）

普通名字走系统 OCR + 完整解包库，不继续按单个忍者增加截图模板。`data/vision_catalog.json` 是 `assets/game/vision_catalog.json` 的逐字节副本，含2490条目录记录（包括变体/内部项，不等于2490名可玩忍者）；启动时解析出518个不同基础名称字段。运行时也读取配置表旁的 `vision_catalog.json`，数据更新不需要修改人物代码。仅解析名字，不读取旧冷却值作为计时规则。

名字从目录 `ninjas[].name` 以及同记录101/501/601/901槽中 `普通攻击/密卷技/通灵兽技/替身术` 的通用前后缀格式提取。HUD 完整姓名必须精确匹配；2026-09-08 的实录证实任意添加 1～2 个汉字前缀会把背景噪声「一」误确认为「一神秘面具男」，因此已移除此规则。目录中只收录简称的少数既有完整姓名在 `data/hud_names.json` 逐条列明来源，必须同时存在对应目录名、OCR 完整拼写完全相等；不参与模糊候选，也不替换错字、搜索昵称或推测版本。扩展更多姓名时补充明确依据，不能恢复任意前缀通行。

- `Ninja`：原有严格文字/版本共识。手动设置、特殊图像模板仍优先。
- `Candidate`：标题起始位置与表中至少四字的基础名至多差一字，且最佳结果唯一、两个视图匹配、两次不同采集时间重复；只显示“名字（待确认）”。不搜索玩家昵称内部，不补全缺字，不猜版本。多个候选同分或证据不足则不显示候选。
- 两种字段分开传递。候选绝不进入 `opponentNinja`、扩槽、配色、自动认边或15/10秒规则；像素变化、切场景、关闭 OCR 按原规则立即失效。
- 都没有时前端明确显示“忍者未确认”，不再用空白让用户误以为已识别。

显示层对已确认名字另有独立短期记录：丢字前300ms不让文字闪灭，持续丢字标注“待复核”，超过2秒清空。VS换人、明确结束画面、几何/布局变化与时间回退会清除显示记录。记录不进入 `opponentNinja`、采豆或任何计时规则，不用旧名字补新的观测。

新提供的鹿丸截图实际 OCR 为“奈良鹿九”，库中该普通版本主要只有简称“鹿丸”；两字中一字错误不足以可靠匹配，当前仍显示“忍者未确认”，**未解决该字体的精确 OCR 错字**。之前手写全名映射生成的“奈良鹿丸（待确认）”实验已撤销，旧实验日志/预览仅为历史证据，不代表当前实际识别结果。该原图采豆确认为左3/右2，未复现用户另一张浮窗中的右侧未知，采豆阈值未改。

## 处理流程

1. 主循环按当前 HUD 标定获取两侧姓名区，生成高对比白色字形签名。只把需要识别的新裁图交给后台；从不等待 OCR 完成。
2. 单个后台工作者以普通/反色及两种整数倍率构成三个视图，使用 Windows 已安装的 zh-Hans-CN OCR。进程持久复用，不逐帧启动。
3. 三个视图中至少两个账号/完整版本相同，才形成候选；还需两次不同采集时间的结果相同。
4. 消费结果时必须满足场景、几何、代次、2秒时效。OCR提供字坐标后，忍者/账号分别绑定当时读出的字形区域，每帧核验当前像素；无可用字坐标才退回整条搜索区签名检查。禁止使用迟到结果换边或延续旧版本。
5. 我方账号必须与用户配置**完整相等且只在一侧出现**。不将白/自、冥/具当成同一个字，也不做包含匹配。未配置的对方账号仅留在显式诊断报告中，不提升为已知身份。
6. 原有模板优先，手动边和忍者版本选择优先。文本不会扩展4/6槽，也不会改变颜色规则。仅完整「照美冥[五代目水影]」遵循用户规定的15/10秒候选计时。

## 隐私与资源

- 不上传、不读取游戏内存、不注入、不发送游戏操作。原始截图和名字仅经匿名管道在本机传递。
- 正常运行不保存 OCR 裁图、原始文本或错误堆栈。用户通过诊断窗口开启对局录制时会保存包含名字的原帧/HUD证据；显式调用 timer-lab ocr -out 可输出三个处理版本的文本诊断报告。
- 最多一个在途任务、一个结果，没有全帧队列。单次3秒超时、失败5秒退避；场景切换不重置后端失败退避，迟到失败同样计入后端状态，但迟到文字不能认人。
- 失败/超时的请求回收子进程后才注销它；清理最多另等1秒，异常时保留进程登记并返回错误，避免误称已退出或同时启动多个助手。窗口关闭即停止主循环，迟到采集和已排队的界面刷新不再改动窗口。
- 文字状态来自当前证据和任务，而不是上次成功的标签；姓名消失不能继续显示已核对，重试中不继续显示上次失败。
- 隐藏的固定系统 PowerShell 执行内嵌脚本；图片与文字是 JSON 数据，从不拼进脚本。不搜索 PATH/current directory，不下载语言模型，不改变系统执行策略。
- 系统没有中文 OCR 或受本机策略限制时，设置窗口显示不可用，继续使用原模板/手动选择。

## 证据与限制

### 名字反复消失修复（2026-09-07）

旧逻辑会因搜索区里远离姓名的白色背景像素变化而清空整侧状态；为另一侧重试而得到的空OCR结果也会清空已识别的一侧。另有远处背景小块被OCR拼进标题首尾的问题。

- 按OCR字框的距离分组，仅剔除跨越两个字高以上空隙、宽度不足主体三分之一的孤立小块；较大分组或紧邻姓名的字不删除。不按人物名字写特例，不替换错字。
- 字框映射回原分辨率，保存本次OCR实际读出的白字及黑边局部证据（仅内存）。各小字形分块都须匹配当前画面，允许统一1像素对齐及轻微亮度差异。不是只比整个长名字的平均相似度，也不是无条件延长旧名字缓存。
- 名字与账号独立核验；账号包含两侧括号，不能把长账号前缀当短账号。远处背景变化、另一侧的空OCR重试不再清除当前仍匹配的字段。实际字形改变、遮挡、场景/几何改变、关闭识别、时间回退仍会撤销对应证据。
- 只有基础名时，后续完整版本仍须两次不同采集时间的完整共识和当前完整字形验证，不能被已识别基础名锁死。全部已知时每2秒后台复查；缺失时仍用400ms提交间隔，一个工作者、无截图积压。
- 原图勘九郎经真实Windows OCR及加入背景扰动的离线回放验证，不依赖前端2秒显示记录。新多由也原图现在可确认基础名；三个视图的「秽土转生」仍不一致，完整版本不补全。初次OCR漏字/错字仍可能拒识；此修改不是全部忍者准确率保证。

局部字形相似度是视觉证据，不是逐字无误的证明。两次一致OCR仍可能同样读错；持续相同字形上的错误结果也可能保留，直至字形改变或场景重置。尚无自然连续视频证明所有战斗特效都不会造成丢读。

1366×768 实图中的「山中井野（白方小）」已在没有姓名模板的目录运行验证，进入正式实时结果。其他950宽实图能补充小南等基础名字，但部分姓名和账号含错字，被共识或字典检查拒绝。重复一致仍不等于无错字，不报告未测准确率。
缺少五代目水影自然截图，故该版本的OCR路径只有严格版本逻辑/合成文字测试，不能声称其真实视觉识别已验证。特殊忍者原图仍走既有精确模板。
