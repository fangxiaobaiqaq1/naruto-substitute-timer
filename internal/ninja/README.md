## 安全界限

- 只有确认名字才扩展六槽、启用红紫配色；纯红特效不能直接创造六颗豆。
- 每侧的4/6槽独立。变化时重校豆数基线，不从拓扑改变推导替身。
- 字体缩放采用参考内容宽度，不能从一个整数四舍五入成15或16的间隔推算，否则整串名字会被错误拉伸。
- 逐帧校验上次命中的名字小块；校验失败立即返回未知，不返回缓存名字/配色/置信度。原位置可作为最多1秒的重试提示，让文字恢复的下一帧立即按原0.80阈值核验，不再额外等待500ms。全范围搜索仍最多每500ms一次，避免反复明暗闪烁绕过限频。
- 短暂丢字期间保留已验证的4/6槽结构和仅供当前像素判色的皮肤提示；绝不复用旧豆数、旧倒计时或旧名字。暗豆可由当前像素继续显示；十尾带土仅在当前格有强紫色豆体、且未命中大范围特效保护时显示亮豆。白光、金色/红色特效与其他没有当前像素证据的豆仍为未知，不参与计时投票。超过1秒、几何变化或时间回退丢弃提示；真实换人仍需重新建立当前画面的豆数基线。
- 没有五代目水影图，不内置伪造模板，不把其他照美冥误归到五代目。目前可在设置中选择完整版本启用双计时；自动视觉识别待补对应实图。

## 2026-09-16 连续扫光修复（11:48 视频反馈）

用户的 6 秒桌面视频显示左右豆数间歇变为问号，不仅是名字模板问题。使用同一训练场的 SDK 原帧复现：修改前 12 秒 409 帧中 131 帧至少一侧未知，名字、场景与采集正常。桌面视频经过压缩缩放，不能将其中的额外姓名匹配失败当成 SDK 原帧行为。

- 通用空豆判定：中心被水平白光/彩色扫光照亮时，必须同时看到当前帧上下连续的暗色内部和左右更亮的边框，才能继续判为空豆。整片遮挡、仅一边边框或仅半边暗色不提供票数；不使用历史豆数。
- 紫豆判定：槽隙使用标定豆间距，避免将 25px 间距的一半误取为整数核心宽度的两倍；同一帧相邻扫描行汇总对比，允许缩窄的菱形下部只有中心加一个内侧像素，但两侧槽隙仍须分别有充分颜色/亮度分隔。
- 紫色和六槽红橙豆的下方探针移到扫光尾端之外；红橙扫光只有在当前上下豆体和槽隙证明充分时才能越过特效保护。保持名字阈值、未知核心阈值、替身确认帧数与事件时间规则不变。

本机证据：`debug/mixed-bead-flicker-20260916-before/`、`-native/`、`-after/`、`-after2/`。新增回归覆盖 89 帧 SDK 录制及两轮诊断图；按实际采集时间回放不产生替身事件，显式合成的双侧掉一豆仍在首次掉豆帧起计。另有普通、紫、红、六槽配色的空豆扫光、完整遮挡、单侧边框、半边豆体和亮豆反例测试。原帧不提交仓库。

## 冷却含义

15秒、10秒是同一次已确认替身的两种候选。候选倒计时不各自产生事件；10秒结束后显示就绪，15秒继续到零。换边、清零以及新替身都基于同一个SideClock事件时间。
